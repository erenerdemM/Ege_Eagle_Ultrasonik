## 5. Explanation of Why `t_set_sure` Remains `000`

1. When `arayuz.HMI` is compiled and launched in the Nextion Editor Simulator, the default startup value for `t_set_sure.txt` defined in the layout is `"000"`.
2. Because the simulator was not receiving external serial bytes through an attached COM port, the simulator's internal instruction parser was never triggered.
3. Therefore, `t_set_sure` visually stayed at its initial default text `"000"`.

## 7. Required Correction to Complete Visual Rendering

To achieve live visual rendering on the Windows Nextion Simulator screen without modifying any firmware or HMI files:

1. **Step 1:** Run a virtual null-modem COM port pair (e.g. `com0com` `CNCA0` $\leftrightarrow$ `CNCB0` or a Python virtual COM port).
2. **Step 2:** Start the bidirectional TCP redirector on Windows PC:
   ```cmd
   python -m serial.tools.tcp_serial_redirect -p COM_PORT -b 115200 100.99.150.99 8888
   ```
3. **Step 3:** In Nextion Editor Simulator $\to$ **User MCU Input**, select the paired COM port at `115200` Baud and click **Start**.
4. **Step 4:** Mirror frames from `/dev/ttyACM0` will immediately reach the simulator, rendering `t_set_sure.txt="15"` and live temperatures in real-time.
