# RULE 04 — ESP32 FREERTOS & NEXTION HMI INTEGRATION

## Purpose
Enforce ESP32-S3 FreeRTOS multi-threading, queue handling, non-volatile NVS recipe storage, 100Hz zero-cross timer simulator, and Nextion HMI display synchronization rules.

## Scope
Applies to all files within `esp32/` and `EKRAN/`.

## MUST
1. Write C++ code compliant with **FreeRTOS** best practices (tasks, queues, mutexes, software timers).
2. Protect shared resources (UART buffers, recipe arrays) using FreeRTOS mutexes (`xSemaphoreCreateMutex`).
3. Handle Nextion HMI serial packet parsing using thread-safe ring buffers and double-buffer state updating (`ekran_kontrol.ino`).
4. Apply a strict 3000ms connection watchdog for slave node heartbeat monitoring.
5. Use ESP32 NVS flash storage for persistent recipe configuration saves with CRC integrity validation.

## MUST NOT
1. DO NOT invoke blocking `delay()` calls in core FreeRTOS task loops; use `vTaskDelay()` or `vTaskDelayUntil()`.
2. DO NOT perform raw NVS writes without verifying key name length (max 15 chars) and payload bounds.
3. DO NOT block Nextion HMI serial RX task with heavy computation.

## Verification
- Run `test_hmi_mock.py` to verify Nextion protocol parsing and UI update response times.

## Escalation
If Nextion display UART communication suffers frame drops or queue overrun, escalate to `communication-specialist` for buffer tuning.
