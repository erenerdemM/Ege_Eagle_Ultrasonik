# RULE 03 — STM32 FIRMWARE & HARDWARE PERIPHERALS

## Purpose
Enforce STM32G474RE HAL library usage, MISRA C compliance, safe interrupt handlers, TIM15 PWM phase control, and OPAMP3 PT100 signal conditioning rules.

## Scope
Applies to all files within `STM32/`.

## MUST
1. Always use **STM32Cube HAL libraries** (`HAL_TIM_`, `HAL_UART_`, `HAL_ADC_`, `HAL_OPAMP_`).
2. Write C code compliant with **MISRA C** standards: explicit types (`uint8_t`, `uint32_t`, `float`), no uninitialized local variables, no unsafe type casts.
3. Keep Interrupt Service Routines (ISRs) minimal and fast. Clear interrupt flags immediately using HAL macros (`__HAL_UART_CLEAR_FLAG`, `__HAL_TIM_CLEAR_IT`).
4. Apply soft-start algorithms and duty cycle limits (0% to 100% clamping) for ultrasonic PWM (`ultrasonic_pwm.c`) and triac heater control (`heater_relay.c`).
5. Ensure PT100 ADC readings (`pt100_adc.c`) apply moving average window filtering and hysteresis guard bands (±1.0°C).

## MUST NOT
1. DO NOT access STM32 registers directly when a standard HAL library API exists.
2. DO NOT perform blocking delays (`HAL_Delay()`) inside ISRs or critical PWM timing loops; use non-blocking `HAL_GetTick()` checks.
3. DO NOT modify `.ioc` hardware configuration without updating corresponding pin definitions in `main.h`.

## Verification
- Code must pass `code-reviewer` MISRA C audit.
- Run `test_hil_uart.py` to verify UART telemetry compliance.

## Escalation
If HAL drivers exhibit hardware silicon bugs (e.g. STM32G4 Errata), document the workaround in code comments and notify `system-architect`.
